 # 经验教训 · 开发过程中的问题记录

 ## 教训 1：中文编码问题
 **问题**：使用 PowerShell 的 `Get-Content` 读取 UTF-8 文件时，系统默认 ANSI 编码会导致中文乱码；再用 `Set-Content` 写回后，中文全部损坏。
 **正确做法**：
 ```powershell
 # ✅ 正确：明确指定 UTF-8 编码读写
 $content = [System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)
 # 修改内容...
 [System.IO.File]::WriteAllText($path, $newContent, [System.Text.Encoding]::UTF8)
 ```
 **恢复方法**：`git checkout HEAD~N -- <files>` 回退到损坏前的版本，重新用正确方法修改。
 
 ## 教训 2：需求变更要先更新 Spec
 **问题**：用户提出新需求后直接开始编码实现，没有先更新 PRD/Design/Checklist。
 **正确流程**：需求变更 → 更新 Spec 文档 → 用户确认 → 编码实现。
 
 ## 教训 3：小步提交的意义
 12 次有意义的提交让编码损坏后能够精准回退到未损坏的版本，而不是全部重做。
